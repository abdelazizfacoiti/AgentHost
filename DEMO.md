# AgentHost Demo and Manual Verification Guide

AgentHost is a Linux-first, provider-agnostic local capability runtime and
visual copilot. This guide covers the supported local demos and the manual
checks that complement the automated test suite.

The demos are intentionally bounded: visual surfaces report runtime state but
do not click, type, navigate, send, submit, upload, delete, pay, or control a
target application. Scheduler records, workflow replay, and Control Room
projections remain non-executable.

## Prepare the repository

From the repository root:

```bash
npm install
npm run build
npm test
npm run lint
npm run smoke:mcp
```

No command in this guide installs system packages or uses `sudo`.

## Visual Copilot runtime demo

The launcher uses authoritative redacted runtime activity and the same overlay
coordinator used by MCP work. It does not use a synthetic walkthrough or a
target-application fixture.

Inspect renderer support without showing an overlay:

```bash
npm run demo:visual-copilot -- --diagnose
```

Run the deterministic headless lifecycle (suitable for CI or a server):

```bash
npm run demo:visual-copilot -- --headless
```

Request a real visible renderer and fail closed if it cannot prove visibility:

```bash
npm run demo:visual-copilot -- --require-gui
```

With a supported desktop, the default command also attempts the configured
renderer:

```bash
npm run demo:visual-copilot
```

Visible mode currently targets Linux X11 with GTK3/PyGObject, PyCairo, and
`xdotool`. Check those prerequisites in the same desktop session:

```bash
echo "$XDG_SESSION_TYPE"
test -n "$DISPLAY"
command -v xdotool
python3 -c "import cairo; import gi; gi.require_version('Gtk','3.0'); gi.require_version('Gdk','3.0'); from gi.repository import Gdk, Gtk; print('gtk3-cairo-ok')"
```

The renderer lifecycle is bounded child startup, authenticated handshake,
epoch assignment, transparent mapping, draw-ready acknowledgement, live
registration, and projection refresh. A headless acknowledgement or an opaque
mapped window is never reported as visible success. Wayland or missing
dependencies receives an honest unavailable/fallback result.

Manual visible checks:

1. Run `--diagnose` and confirm the reported session/display and GTK status.
2. Run `--require-gui` and confirm the runtime activity surface appears and
   reaches verified `completed` state.
3. Confirm focus, the real pointer, and the target application are unchanged.
4. Press Ctrl-C during the run and confirm owned surfaces disappear and no
   renderer process remains.

## Browser bridge setup

The browser bridge is disabled by default, loopback-only, and paired manually.
For local setup diagnostics:

```bash
npm run browser:setup
```

Load the unpacked Firefox or Chromium extension from the printed repository
directory, enable it, and paste the pairing token generated by AgentHost into
the extension popup. The bridge exposes only fixed structured commands; it
does not expose cookies, passwords, storage, arbitrary JavaScript, or direct
selector execution. Browser element actions use short-lived opaque `elementId`
references.

Use a public or local test page for manual checks. Communication, financial,
credential, and administrative pages remain policy- and grant-gated.

## Control Room (optional)

The local read-only Control Room is disabled by default:

```bash
AGENTHOST_CONTROL_ROOM_ENABLED=1 npm run start:mcp
```

Use the loopback URL and temporary token printed by AgentHost. Verify that
dashboard, task, health, timeline, and screenshot metadata projections are
bounded and redacted. The Control Room cannot execute tools, approve
confirmations, grant permissions, replay skills, run scheduler jobs, or
control target applications.

## Safety and non-execution boundaries

- Visual events are operator intents only; they never invoke another tool.
- Scheduler records support review-only metadata and lifecycle state, not
  timers, workers, notifications, delivery, or job execution.
- Workflow replay prepares and verifies one step at a time; it does not run in
  the background or bypass the original tool's safety checks.
- Logs, receipts, metrics, screenshots, OCR, and Control Room projections must
  not contain secrets, tokens, raw private page content, or screenshot bytes.

## Automated verification

Run the standard gates from the repository root:

```bash
npm run build
npm test
npm run lint
npm run smoke:mcp
git diff --check
```

Release validation additionally uses `npm run release:preflight`,
`npm run release:build`, `npm run release:scan`, and
`npm run release:verify`. These checks do not claim visible pixel success;
that still requires a normal supported X11 desktop.
